# Architecture Review
Generated: 2026-09-01T06:34:21.476Z
Score: 66/100

## Summary
The codebase has a clear component library layer (Card, Amount, ScreenScaffold, etc.) with good 'Pre-built' documentation discipline, but the domain-type layer is fragmented across three overlapping files (lib/types.ts, lib/contract.ts, types/domain.ts) with at least one genuine shape divergence in BillBreakdown. There's also a leftover scaffold contract file that's almost entirely dead code, several small utilities/hooks reimplemented ad hoc instead of reused (haptics, storage-key loading, YoY/type-guard logic, currency formatting), and inconsistent import-path and data-access conventions across pages.

## Issues
### Critical
- [duplication] BillBreakdown/StageBreakdown are defined independently in src/lib/types.ts and src/types/domain.ts with different shapes — lib/types.ts's version omits climateCharge and fuelCharge, which domain/calculateBill.ts's return object never actually sets on its declared type, while types/domain.ts's richer version is presumably what consumers expect (Result.tsx pulls CLIMATE_RATE/FUEL_RATE separately to work around this). — Files: src/lib/types.ts, src/types/domain.ts, src/domain/calculateBill.ts, src/pages/Result.tsx / Fix: Delete one of the two BillBreakdown/StageBreakdown definitions and have calculateBill.ts import the single canonical type from src/types/domain.ts (or move all domain types there and have domain/*.ts import from it).

### Suggestions
- [consistency] Won/currency formatting is implemented two different ways: History.tsx uses `n.toLocaleString('ko-KR') + '원'` while Report.tsx, Result.tsx, and Simulate.tsx use `formatNumber(n) + '원'` (Intl.NumberFormat via lib/utils). Functionally similar but not shared. — Files: src/pages/History.tsx, src/pages/Report.tsx, src/pages/Result.tsx, src/pages/Simulate.tsx / Fix: Add a single `formatWon(n)` helper in lib/utils.ts and use it everywhere instead of ad hoc `won()` locals with two different underlying formatting calls.
- [structure] Import style is inconsistent between relative paths (App.tsx, Home.tsx, History.tsx use '../lib/storage', './rateTable') and the '@/' alias (Result.tsx, Simulate.tsx, Report.tsx, ApplianceSheet.tsx use '@/lib/storage', '@/components/Card') with no apparent rule for which files use which. — Files: src/App.tsx, src/pages/Home.tsx, src/pages/History.tsx, src/pages/Result.tsx, src/pages/Simulate.tsx / Fix: Standardize on the '@/' alias project-wide (already configured and used by most newer files) and run a codemod/lint rule (e.g. no-relative-parent-imports) to enforce it.
- [dead_code] src/lib/storage.ts keeps a 'Legacy API' (getItem/setItem/removeItem) explicitly marked as kept for backward compatibility, but no shown file calls it — all consumers use readJSON/writeJSON. Similarly, cn() and formatCurrency() in lib/utils.ts appear unused (only formatNumber is referenced anywhere). — Files: src/lib/storage.ts, src/lib/utils.ts / Fix: Grep the full repo for getItem/setItem/removeItem/cn/formatCurrency usage; delete if truly unreferenced, or move formatCurrency next to formatNumber usage if it's planned for near-term use.
- [structure] The 'domain' concept is split confusingly: business logic lives in src/domain/ (calculateBill, compare, rateTable, simulate, stage, validate) while a same-named but unrelated src/types/domain.ts holds general data-model types, and src/lib/types.ts holds a third, overlapping set of bill-calculation types. — Files: src/domain/rateTable.ts, src/types/domain.ts, src/lib/types.ts / Fix: Rename src/types/domain.ts to src/types/models.ts (or similar) to disambiguate from src/domain/, and consolidate all bill-calculation types into src/domain/ instead of leaving a copy in lib/types.ts.
- [naming] src/pages/__TdsGallery.tsx uses a double-underscore prefix convention not used by any other file in the codebase (all other pages are plain PascalCase: Home.tsx, Result.tsx, etc.), making it a one-off naming convention a reader has to learn just for this dev-only file. — Files: src/pages/__TdsGallery.tsx / Fix: Either keep the convention but document it once in a project README/CLAUDE.md as 'dev-only pages are prefixed with __', or move it out of src/pages into a src/dev/ folder to avoid mixing conventions within the same directory.
