# Architecture Review
Generated: 2026-09-01T20:10:56.481Z
Score: 74/100

## Summary
The codebase has a clean, consistent layered structure (domain/lib/components/pages) with pure calculation functions well isolated from storage and UI concerns, and no circular dependencies were found. The main weaknesses are copy-pasted cross-cutting logic (haptics, full-screen ad gating, storage access) that should be centralized, plus a drifted 'contract.ts' file and a couple of unused components/files left in the tree. None of the issues are architecturally severe, but they add maintenance risk as the app grows.

## Issues

### Suggestions
- [duplication] Two full-screen/reward-ad gating implementations exist with overlapping responsibility: `ReportGate.tsx` (used by Report.tsx) and `TossRewardAd.tsx` (generic reward-ad gate, not referenced by any page in the codebase). Both independently call `loadFullScreenAd`/`showFullScreenAd` and manage `adLoaded`/`isShowing` state. — Files: src/components/ReportGate.tsx, src/components/TossRewardAd.tsx / Fix: Extract a shared `useFullScreenAd()` hook containing the load/show/timeout state machine, and have ReportGate (and TossRewardAd, if still needed) consume it instead of duplicating the imperative SDK glue.
- [dead_code] `src/lib/contract.ts` declares several type aliases (`DomainInput`, `RouteState`, `calcBillFn`, `roundToNearestFn`, `settingsStoreFn`, `useQuotaToastFn`, `SummaryHero`, `YoYCard`, `ApplianceStepperCard`) that are not imported/used as type annotations by their supposed implementations anywhere in the shown code — only `Bill` and `recordStoreFn` are actually consumed (by recordStore.ts and compare.ts). The rest appear to be documentation-only scaffolding that never enforces the contract at compile time. — Files: src/lib/contract.ts, src/domain/validation.ts, src/lib/settingsStore.ts, src/hooks/useQuotaToast.ts / Fix: Either wire the implementing functions to actually satisfy these contract types (`export const validateUsage: validateUsageFn = ...`) so drift is caught by the compiler, or remove the unused aliases and keep contract.ts limited to types that are genuinely enforced.
- [duplication] `monthLabel` is independently implemented three times with slightly different signatures/output: YoYCard.tsx (`'${month}월'` from a yearMonth), History.tsx and Result.tsx (`'${year}년 ${month}월'`). — Files: src/components/YoYCard.tsx, src/pages/History.tsx, src/pages/Result.tsx / Fix: Move a single parameterized `formatYearMonth(ym, { withYear })` helper into lib/utils.ts and reuse it in all three places.
- [structure] Static/reference data is split inconsistently between `src/domain/` (appliances.ts, tariff.ts, tips.ts — plain data tables, not pure functions) and `src/data/` (region-average.json), making it unclear where new static datasets should live. — Files: src/domain/appliances.ts, src/domain/tariff.ts, src/domain/tips.ts, src/data/region-average.json / Fix: Adopt one convention, e.g. keep `domain/` strictly for pure calculation functions and move constant data tables (appliances, tariff, tips) into `src/data/` alongside region-average.json.
- [consistency] Nearly all UI components style via inline `style` objects using CSS variable tokens, but `TossRewardAd.tsx` and `TossPurchase.tsx` instead use external CSS classes (`@/styles/reward-ad.css`, `toss-purchase-button`), breaking the otherwise uniform styling approach. — Files: src/components/TossRewardAd.tsx, src/components/TossPurchase.tsx / Fix: Convert these two components to the same inline-style/adaptive-token pattern used everywhere else, or explicitly document why they are exempt (e.g. third-party embed requirement).
- [naming] Several component files export component(s) whose name doesn't match the filename, breaking the file-name-equals-export convention followed by most of the codebase (Card.tsx→Card, SummaryHero.tsx→SummaryHero, etc.): BottomCTA.tsx exports `SubmitFooter` (+ a second CTA component), and StateView.tsx exports `EmptyState`/`LoadingState`. — Files: src/components/BottomCTA.tsx, src/components/StateView.tsx / Fix: Either rename the files to match their primary export (e.g. `SubmitFooter.tsx`) or, if a file intentionally groups multiple related components, document that convention so it isn't mistaken for inconsistency.
- [dead_code] `lib/utils.ts` exports `cn` and `formatCurrency`, neither of which appears used anywhere in the shown codebase (Amount.tsx/CountUp.tsx use `formatNumber` only, and no component uses a `cn` classname helper). — Files: src/lib/utils.ts / Fix: Verify usage with a project-wide search; remove unused exports or wire them in where intended (e.g. formatCurrency for a price display) to avoid drifted dead utilities.
